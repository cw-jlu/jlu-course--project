# weX – JLU 软件学院  
## 面向对象程序设计课程设计（大二上）

---

### 1 课程设计目的
1. 熟悉利用面向对象方法与 C++ 编程思想完成系统设计；  
2. 建立清晰的类层次，应用继承、多态等 OOP 技术；  
3. 加深对《面向对象程序设计》课程知识的理解，掌握 C++ 语法规范，编写结构清晰、风格良好的 C++ 程序，具备利用编程解决综合问题的初步能力。

---

### 2 课程设计题目  
**模拟即时通信系统实现**

#### 2.1 业务背景
腾讯公司旗下拥有 QQ、微信、微博等社交服务，未来可能继续推出微商、微唱、微走、微笑等「微 X」产品。公司希望整合成统一的立体社交平台，本次课程设计即完成该平台的核心原型。

---

### 3 功能需求

#### 3.1 用户基本信息
| 字段 | 说明 |
|---|---|
| ID | 号码唯一标识 |
| 昵称 | 用户昵称 |
| 出生时间 | 日期类型 |
| T 龄 | 号码申请时间 |
| 所在地 | 字符串 |
| 好友列表 | 容器 |
| 群列表 | 容器 |

&gt; 微博与 QQ 共享 ID；微信采用独立 ID，可与 QQ 绑定；其余「微 X」产品分这两种情况。

#### 3.2 好友管理
1. 添加、修改、删除、查询好友信息；  
2. 查询微 X 间共同好友（如微信可推荐 QQ 好友）。

#### 3.3 群管理
1. 预设群号：1001 … 1006；  
2. 加入群、退出群、被踢、查询群成员；  
3. 不同微 X 群特性差异：  
   - QQ 群：允许申请加入、支持临时讨论组、群主+管理员制度；  
   - 微信群：仅可推荐加入、无子群、仅群主特权。

#### 3.4 开通管理
用户可自主选择开通 N 个「微 X」服务。

#### 3.5 登录管理
任一服务登录后，其它已开通服务简单确认即自动登录。

#### 3.6 功能展示（main 函数约定）
1. 开通情况、群成员、好友信息**预存文件**，启动时加载；  
2. 一个服务登录后，其余服务**全部进入开通状态**；  
3. 可依据**任意已开通服务**的好友列表跨服务加好友；  
4. 动态展示当前群特色，并可在**不伤害群成员数据**前提下切换管理模式；  
5. **选做**：QQ 点对点 TCP 通信（需加载 `ws2_32.lib`，了解 `bind` / `listen` / `accept` / `connect` / `send` / `recv` 等 API）。

---

### 4 技术层次要求

| 层次 | 要求 |
|---|---|
| 基本 | 完成功能即可，技术不限，允许面向过程。 |
| 对象 | 正确切割类，利用对象技术；容器类如「微 X 成员管理」；实体类如「微 X 信息 / 群信息 / 好友信息」。 |
| 抽象封装 | 继承或组合复用；提供接口保护数据成员；好友 / 群维护均以接口形式暴露。 |
| 多态 | 支持多态，遵循设计原则（如开闭、里氏替换）。 |
| 优化提高 | 数字菜单、文件 I/O 断电保存、可扩展、群管理模式动态可变、必要注释、UML 类图、类名后缀加姓名缩写（例：`TencentZhS`）。 |

---

### 5 设计步骤（参考）

#### 5.1 确定类及关系
- 从描述中抽取**概念或实体**→ 建类；  
- 类应**小而简单**（单一职责）；  
- 充分**封装**；  
- 通过**继承**形成类族，方便多态。

#### 5.2 类实现要点
- 构造 / 析构策略；  
- 成员函数设计；  
- 提炼命名与功能共性。

#### 5.3 细化类关系
描述类之间**继承、组合、关联、依赖**。

#### 5.4 界面与接口
分离**抽象接口**与**实现**。
